# DynamicPackage 严格数值等价契约

## 目标定义

本项目的主目标不是覆盖或替换原 ELF，而是永久保留经校验的原样本，并在独立目录中建立可编译、可审计的 C 重建实现。每一次比较均以原 ELF 为金标；恢复 C 代码只有在满足本契约时才可被标注为“对齐”。

“数据完全对得上”被拆分成三个可验证层级。第一层是共享内存协议完全一致，即对象名称、大小、锁语义、输入和输出的全部字节偏移一致。第二层是确定性测试中的完整遥测帧逐字节一致。第三层是可观测内部状态逐元素一致，包括 33 维积分状态、设备状态和关键中间向量。默认验收目标是第一、第二层的严格相等；第三层用于定位第二层出现的首个差异。

## 严格比较对象

| 对象 | 比较粒度 | 严格标准 | 备注 |
|---|---|---|---|
| 共享内存对象 | 名称、长度、锁位置 | 完全一致 | 当前已知：`/sharedvars_example`，`0xBF0` 字节 |
| 输入帧 | 所有字节 | 完全一致 | 包括浮点位模式和控制标志 |
| 输出遥测帧 | 所有字节 | 完全一致 | 不只比较已命名字段；保留未命名区域 |
| 整数／标志 | 所有位 | 完全一致 | 不允许容差 |
| 浮点确定性字段 | IEEE-754 位模式 | 完全一致 | 需要固定编译／库／舍入条件 |
| 浮点随机／时间相关字段 | 先固定随机源与时钟后比较位模式 | 完全一致 | 若无法固定，必须显式标为非确定性，不能假称完全匹配 |
| 33 维内部状态 | `double` 位模式优先 | 完全一致；若编译环境无法统一，记录 ULP 差 | 用于首差定位 |
| 错误路径 | 返回码、标志、日志事件 | 完全一致或明确可解释差异 | 使用非法／边界输入向量验证 |

## 获得逐字节一致所必须控制的条件

原程序包含时间、睡眠、数学库和随机数相关依赖。只要这些变量不冻结，即使 C 逻辑正确，输出也可能不同。因此金标采集和重建运行必须固定以下条件：

1. **初始条件**：将共享内存中供 `DynamicDllInit` 和主循环读取的所有参数完整记录，并在每轮测试前重置。
2. **时钟**：拦截或固定 `clock_gettime` 与 `clock_nanosleep` 的返回时间序列，使原 ELF 与重建程序使用同一逻辑时钟。
3. **随机数**：记录／重放 `rand()` 状态与调用顺序，或通过受控动态链接拦截器提供确定性随机序列。
4. **浮点环境**：固定舍入模式、SSE/AVX 行为、浮点收缩、优化级别、`libm` 版本和 CPU 架构；重建代码禁止 `-ffast-math`，并应关闭可能改变运算顺序的融合操作。
5. **线程和调度**：共享内存读写在相同周期边界加锁；每一帧输入和输出必须带逻辑步号，不以墙钟时间判断配对。
6. **编译工具链**：原 ELF 的编译注释显示 GCC 7.5.0（Ubuntu 18.04 系列）。重建的按位一致阶段应使用尽可能接近的工具链和 C 运行库；若不能完全复用，必须通过中间状态找出并消除差异。

## 失败处理规则

任何字节差异都不是“基本一致”，而是一个待定位缺陷。回归器必须输出首个差异的：测试向量 ID、逻辑步、共享内存偏移、字段名（若已知）、原始十六进制、恢复十六进制、上游状态、时钟值、随机序列位置和版本哈希。只有修复首个差异后，才允许分析后续差异，防止误差传播掩盖根因。

## 理论约束的使用原则

轨道、姿态、刚体／柔性体和传感器理论用于为反汇编的变量、矩阵维度、单位、符号和方程候选提供约束，并用于识别明显错误的恢复结果；它们**不能替代原 ELF 的实际观察值**。若理论上存在多个合理公式，以原 ELF 在受控输入下的输出和中间内存访问为最终裁决。反推实现必须优先复刻原程序的运算顺序和边界行为，而不是把模型“改写成更漂亮的教科书公式”。
