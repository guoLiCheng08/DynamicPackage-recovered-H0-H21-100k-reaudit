# DynamicPackage 逐函数反编译与结构恢复路线

## 原则

每一个函数都按照“静态提取 → C 伪代码 → 独立单元测试 → 原 ELF 差分验证 → 合入重建运行时”的顺序处理。不要先写完整大工程再统一调试；那会使矩阵维度、结构偏移、符号含义和数值差异无法定位。

每个恢复函数应配套一份证据卡：原 ELF 地址和大小、调用者／被调用者、访问的全局地址、输入输出寄存器、读取／写入偏移、常数、反汇编文件路径、C 实现路径、单元测试路径、误差统计和可信度等级。

## 阶段 A：建立可测基础库

首先恢复无业务状态、可独立验证的数学函数，并以原 ELF 输出做向量测试。这一阶段应包括 `vector_*`、`matrix_*`、`blas_gemv`、`blas_gemm`、`inv_CAL_M3`、`quat_*`、`matrix2quat`、`quat2matrix`、`Rotation_X/Y/Z`、坐标与时间转换函数。

方法是为每个目标函数写最小 C 调用桥接器，在隔离命名空间内以固定输入调用原 ELF 对应函数，记录返回值和内存输出；再将同一输入送入恢复 C 函数，比较逐元素 ULP、绝对误差和相对误差。对于可通过二进制符号直接调用的函数，应优先使用原 ELF 的函数地址调用；若 PIE 调用桥接复杂，则通过上层共享内存输入和遥测输出观测。

验收要求为：标量／向量和矩阵函数在随机但固定种子产生的至少 1,000 组输入上逐元素误差不超过 1 ULP，且异常输入（零向量、奇异矩阵、角度边界）行为一致。

## 阶段 B：恢复 ABI、IPC 和全局数据结构

下一步不应急于反编译复杂方程，而应将 `g_data`、`input`、`output`、`dynamic_out`、`Sat`、`SADA`、`Wheel`、`STS`、`Gyro`、`DSS`、`MagMeter`、`GPS_Kalman`、`DRC_DATA` 等全局区域恢复为显式 C 结构体。

工作方法包括：对每个全局基址生成所有 RIP 相对引用交叉表，按访问宽度（1、4、8 字节）、数组步长、读写方向和相关字符串聚类；再用 `UpdateMainOut`、`sendDynTele`、`getDynInput` 的已知字段作为锚点，从外到内命名字段。任何未命名区域先用 `reserved_xxx` 保留精确字节长度，禁止为了美观而猜测或压缩布局。

验收要求为：所有共享内存偏移完全一致；输入和输出结构的 `sizeof`、`offsetof` 均带有 `_Static_assert`；原 ELF 的共享内存读写探针能够被重建程序逐字节复现。

## 阶段 C：恢复设备控制与设备动力学

优先顺序为：反作用飞轮、磁力矩器、推进器、SADA，随后是外力／气动力矩。每个模块应先从初始化函数、设置函数、查询函数和单次更新函数构建状态机，再将其纳入 `UpdateDeviceControl` 和 `UpdateDeviceMeasure`。

每个设备模块的差分测试应使用阶跃命令、保持命令、正负边界、使能切换和非法输入。原 ELF 的可观测输出包括 `RW_omega`、`SADA_Feedback`、姿态角速度和部分遥测标志；需要同时比较瞬态响应、稳态值和饱和／限位行为。

## 阶段 D：恢复姿态与柔性耦合核心

`dynamics_flex` 是最高风险函数，应拆分而不是一次性翻译。先根据栈上矩阵大小、`blas_gemm/gemv` 参数、`matrix_trans/sub`、`inv_CAL_M3` 调用，将 2,925 字节函数分成矩阵构建、耦合项、线性方程求解和导数回写四段。每段恢复后都以记录的输入／输出内存块验证。

随后恢复 `CoreDynamic`，明确其是调用 RK4、更新全局时间、更新轨道／姿态状态还是在其间插入设备／传感器逻辑。目标是使 33 维状态向量在每个时间步与原 ELF 对齐。

验收要求为：固定初始条件和固定命令下，连续 100 步的四元数、角速度、位置、速度和 20 维扩展状态都满足预设误差阈值；如果误差在某一步突增，必须退回到该步的子模块中间量比较，而不是调大容差。

## 阶段 E：恢复轨道摄动和传感器模型

`orbit_dynamic` 应按中心引力、坐标转换、J2、J4、气动力／外力、质量归一化的顺序逐项添加。每添加一项都针对位置、速度、不同高度、不同轨道倾角和不同外力单独回归。轨道根数转换函数需要与轨道状态双向一致。

传感器模型按 STS、Gyro、DSS、MagMeter、GPS/Kalman 顺序恢复。重点不是只匹配单帧，而是匹配有效标志、噪声／偏差的随机序列、遮挡／视场边界和时间更新节奏。若随机数影响输出，必须通过记录原 ELF 的随机调用顺序或兼容相同 C 库随机算法来控制。

## 阶段 F：集成、链接与黑盒替换

所有模块进入同一重建运行时后，完成与原 ELF 相同的 `/sharedvars_example` IPC 服务、相同的周期任务和遥测封包。先保持一个“兼容模式”，严格使用原有偏移与数据格式；再在新接口上做重构，避免兼容目标与代码美化互相干扰。

最终测试应由原 ELF 和重建程序在相同私有共享内存输入回放中并行运行。测试控制器每个周期写相同命令、记录两个程序的完整输出快照和内部状态快照；报告最大、均方和 99 分位误差，并保存首个偏离样本的输入和执行上下文。
