# H36：恢复 C11 实现的原理、数值与 ABI 理论审计

**审计日期：** 2026-08-27
**审计对象：** 当前 `main` 分支提交 `ebe8de3` 的活动恢复源 `src/`；`src/dynamic_recovered.c` 是明确标注的旧阅读脚手架，未由当前 `Makefile` 链接，因此不作为生产恢复路径审计对象。
**适用范围：** 当前 Linux x86-64、当前 glibc/libm、默认严格 C11 构建和离线受控测试。

> **审计结论先行：** 未发现任何已被原 ELF gold 证实、却仍未修复的活动主路径算法/字节分叉。当前实现的主要问题不是“已覆盖结果错误”，而是原 ELF 本身及其高保真恢复都具有的未保护数学边界、危险公开 ABI、全局状态和 POSIX 运行时依赖。这些问题使其不适合作为通用健壮数值库或工程安全组件；为保持行为等价，不能在没有原 ELF 对照证据时擅自修正。

## 1. 审计方法与证据强度

本轮先锁定构建与样本基线：工作树干净，原 ELF 保持 `0400`，SHA-256 为 `312678a62afcb64ff9d198d7311db39bece432702cdfb00830d8439d24906403`。活动源以 `-std=c11 -O0 -g -Wall -Wextra -Wpedantic -Werror -fno-fast-math -ffp-contract=off` 构建。当前已有 28 条结构化主 `dyn_main` 路径，140,800 个逐步四块状态/输出检查，累计 568,788 次显式比较和 574,594,185 B 原始字节比对；均为 0-byte mismatch。[1](h0_h20_current_io_coverage_audit.md)

额外使用 GCC `-fanalyzer` 对当前 `Makefile` 活动源逐单元编译，没有诊断。随后以可恢复 UndefinedBehaviorSanitizer 重跑默认受控回归；完整门禁以状态 0 结束。五条 UBSan 诊断全部来自明确标注的死亡测试：三个空 `data` 指针调用，以及 `quat2matrix`/`quat_to_euler_angle_312` 的故意非法地址写入。H35 近抛物千步四块比较在该运行中仍 PASS。该检查仅说明**已覆盖的正常调用路径**未发现新的 UBSan 报告；它不能证明所有公开 ABI 输入没有未定义行为。

| 证据等级 | 含义 | 本轮应用 |
|---|---|---|
| A：双采集原 ELF + 位级差分 | 目标平台上已直接证明 | H0–H35 的受控主路径、H28 数组 ABI、H29/H31/H33 的列明 IPC 合同 |
| B：原 ELF 直接死亡/异常观察 | 目标崩溃或危险行为已观察，但未得到正常返回 ABI | `quat2matrix`、`quat_to_euler_angle_312` 的直接调用边界 [2](../time_orbit/quat2matrix_p3_probe_failure.md) |
| C：源码可证明的理论风险 | C11/数值理论可直接推出，但未形成对应 ELF 全路径 gold | 零范数、奇异矩阵、映射失败后局部未初始化、并发/时区依赖 |
| D：工程适用性判断 | 非行为差异，只评价是否适合作为通用组件 | 固定步长、全局状态、非可移植布局和未验证输入域 |

## 2. 动力学、轨道与数值实现

### 2.1 已验证的数值骨架

轨道传播保留中心引力后接 J2/J3/J4 的加法次序；根数正向转换按 `M2E → sincos → 轨道平面状态 → R3·R1·R3`，而 RK4 保存 `h·k1` 至 `h·k4` 并按 `k4+2k3+2k2+k1` 顺序加权。四元数正规化也保留逐分量除范数，而非倒数乘法。恢复代码对 SSE 左操作数、qNaN 符号和累加顺序的显式保留，是当前位级等价得以成立的关键；不应为“代码简洁”改写。[3](../../src/dynamic_orbit.c) [4](../../src/dynamic_rk4.c) [5](../../src/dynamic_math.c)

H34 已验证严格圆/赤道，H35 已验证 `e=0.99` 且 `sqrt(1-e²)=0.14106735979665884425` 的有限椭圆高偏心根数。H35 的 state、global `y`、main 与 IPC 在 100/1000 步均 bitwise PASS，因此没有证据表明该已覆盖范围存在轨道根数转换或积分分叉。[6](h34_circular_equatorial_result_20260825.md) [7](h35_near_parabolic_result_20260826.md)

### 2.2 未保护数学域：真实风险，但当前不是已证实差异

`M2E` 的牛顿迭代没有输入域验证、导数下限、收敛失败返回码或残差输出；它仅在 10,000 次内以 `|delta|<1e-10` 退出。对 `e≈1` 且相位使 `1-e cos(E)` 很小时，迭代可能病态，随后 `Elements2PosVel_M` 的 `sqrt(1-e²)`、半长轴三次方和分母均可能产生非有限值。`PosVel2Elements_M` 同样直接计算半长轴、`sqrt(mu·a)`、`sqrt(1-e²)` 和 `acos` 参数，没有为零半径、逃逸/双曲状态、接近抛物能量分母、非单位角动量或反余弦轻微越界设置保护。[3](../../src/dynamic_orbit.c)

刚柔耦合以 `J_eff = J - C C^T` 构造有效惯量后，无条件调用 3×3 显式伴随矩阵求逆；`inv_CAL_M3` 对行列式没有阈值或条件数保护。四元数正规化、向量归一化和夹角计算也分别依赖正范数、有限范数与 `acos(dot/(||a||||b||))` 在定义域内。若四元数为零、惯量奇异/近奇异、位置向量为零、质量为零或向量几乎共线，这些路径会产生 `NaN`、`Inf` 或不稳定放大。[5](../../src/dynamic_math.c) [8](../../src/dynamic_flex.c) [9](../../src/dynamic_dynamics.c)

这属于**C 级实现和原模型共同的理论边界**，不是已覆盖有限轨迹中的 C 算法错误。固定步长 RK4 也没有误差估计、自适应步长或刚性稳定性保护；这会限制其在长时域、强耦合或高频柔性输入下的通用数值可靠性，但在当前固定步长/固定样本上，改变它会破坏目标等价。[4](../../src/dynamic_rk4.c)

## 3. C11、ABI、初始化与 IPC 审计

### 3.1 原样保留的危险公开 ABI

`vector_memcpy`、`vector_axpy` 和 `vector_axpby` 对数据指针不作空指针保护；测试明确把这些调用定义为预期 SIGSEGV 的死亡边界。更严重的是，`quat2matrix` 与 `quat_to_euler_angle_312` 目前有意复现原 ELF 已观察到的非法本地 descriptor 地址写入。这在当前平台的直接调用中产生 SIGSEGV，并在 UBSan 下报告未对齐非法地址写入。[2](../time_orbit/quat2matrix_p3_probe_failure.md) [5](../../src/dynamic_math.c)

因此，若问题是“是否保持原 ELF 行为”，这些危险入口不构成已证实分叉；若问题是“是否可作为安全的通用 C API”，它们是**高严重度接口缺陷**。当前仅有死亡边界证据，尚没有可信正常调用点 ABI，因此不能臆造一个“修复后正常返回”的行为版本。

### 3.2 `getDeskCommand` 的映射失败风险

`getDeskCommand` 对所有 getter 返回值显式 `(void)` 忽略。共享映射正常打开时，H29、H31 和 H33 已确认其读取结果、生命周期和 getter 受控错误合同；H33 还证实无效索引/空输出返回码与输出保持。[10](h33_ipc_getter_invalid_result_20260825.md) 但若 `get_float_value` 因共享对象打开失败返回且不写 `x/y/z`，`getDeskCommand` 仍把三个自动局部 `float` 传入初始化状态。按 ISO C 抽象机，这属于读取不确定自动对象值的风险，某些表示可触发未定义行为；在当前 `-O0` 目标环境则更接近原 ELF 的未定义失败状态。

这是一项**中高严重度、未覆盖的失败路径风险**，不是“应立即初始化为零”的改码建议。把局部变量零初始化或改为检查返回码会改变原 ELF 的可观察错误行为，必须先获得安全、离线的原 ELF 映射失败/状态保持证据。

### 3.3 POSIX IPC 与全局状态限制

共享 IPC 依赖固定名称 `/sharedvars_example`、Linux x86-64 下 0x38 字节 `pthread_rwlock_t`、`shm_open`、`mmap` 和 process-shared rwlock。头文件用静态断言锁住当前锁尺寸与映射总大小，这一点优于未断言的通用 ABI 结构；但已有共享对象不做版本、文件长度、初始化完成状态或锁损坏检查，锁返回码也被忽略。写进程异常终止、权限变化、资源耗尽、对象尺寸不符或跨进程竞争，均不在现有证据域内。[11](../../src/dynamic_ipc_telemetry.c) [12](../../src/dynamic_ipc_telemetry.h)

动力学还使用全局 `y`、时间、惯量、外力、执行机构和前一磁场状态。因此它不是可重入的，也不是线程安全的；两个并发实例会相互污染全局状态。`TimeInit`/`TimeAdd` 使用进程本地 `struct tm` 和 `mktime`，且保留小数秒残量/累计秒；跨时区、DST、负步长、重复初始化残量语义和异常历法尚未形成完整 gold。[13](../../src/dynamic_time.c) [14](../../src/dynamic_satellite_globals.c)

### 3.4 ABI 固化不足与已知启动覆盖缺口

设备、传感器与 IPC 结构含有大量活动 `_Static_assert`，但 `DpDynInput` 偏移和 `DpState` 大小的部分关键断言仍位于未参与当前 `Makefile` 链接的历史 `dynamic_recovered.c`。当前平台的 0x78、0x108、0x148、0x220 原始块 gold 已间接确认实际布局，但若未来调整头文件、切换编译器选项或移植架构，缺少活动编译单元的断言会降低早期发现 ABI 漂移的能力。[15](../../src/dynamic_recovered.h)

此外，`DynamicDllInit` 源码自身明确限定目前恢复并验证的是“共享输入不可读时”的默认启动分支；共享输入索引 64/65/66 成功返回分支、诊断标准输出和部分传感器内部对象仍未得到同等级闭环。该项是**覆盖缺口**，不是被测试证明为错误的代码路径。[16](../../src/dynamic_dll_init.c)

## 4. 风险分级与处理原则

| 编号 | 发现 | 等级 | 与 ELF 等价关系 | 当前处理原则 |
|---:|---|---|---|---|
| R1 | 已覆盖的有限主路径中无字节分叉 | 结论 | A 级直接证据 | 不修改已验证数值数据流 |
| R2 | 零范数、零半径、`e≥1`、奇异惯量、`acos` 越界缺少保护 | 高 | C 级理论风险；可能是原 ELF 同行为 | 单步预筛后再取证，不能擅自钳位/返回零 |
| R3 | 固定步长 RK4 无自适应/刚性保护 | 中 | 工程限制，不是等价错误 | 作为离线受控积分器使用；不外推长时域精度 |
| R4 | `getDeskCommand` 映射失败后可能使用未初始化局部角速度 | 中高 | 未完成原 ELF 映射失败取证 | 优先建立安全失败合同；暂不更改返回码处理 |
| R5 | `quat2matrix`、`quat_to_euler` 与空数据指针入口可崩溃 | 高 | B 级死亡边界与原 ELF 对齐 | 明确隔离；不能作为安全 API 暴露 |
| R6 | IPC 固定名称/锁尺寸、无对象版本与竞争恢复 | 中高 | H31/H33 只覆盖无竞争成功/受控错误 | 不做破坏性竞态；仅安全单项失败取证 |
| R7 | 全局状态、`mktime` 时区/DST、非重入性 | 中 | 当前平台约束 | 同一进程单实例、固定时区和受控时间；勿并发调用 |
| R8 | 活动 ABI 断言覆盖不完整 | 中 | 当前 gold 隐式验证当前布局 | 未来可增加无行为变化的活动 `_Static_assert`，但先完成原 ELF/构建影响审查 |
| R9 | `DynamicDllInit` 共享输入成功分支未闭环 | 中 | 明确覆盖缺口 | 作为后续入口取证，而非推断为实现错误 |

## 5. 最小风险的后续取证顺序

第一优先级是 H37：对 `getDeskCommand` 的共享映射失败路径做不破坏共享对象的原 ELF 安全观察，比较 flags、初始角速度尾部与 DRC 是否保持，并明确失败时是否允许读取未初始化局部。第二优先级是 H38：对 `M2E`、`Elements2PosVel_M`、`PosVel2Elements_M` 和 `inv_CAL_M3` 选择有限/非有限边界的**单步**函数级 probe；只有原 ELF 输出稳定、调用不崩溃且非有限位型可控时，才进入主轨迹。第三优先级是 H39：在固定 `TZ` 条件下审计重复 `TimeInit`、负 `TimeAdd` 与跨月/跨年，以区分原有语义和平台依赖。随后可考虑 H40：补全 `DynamicDllInit` 的 64/65/66 成功输入分支。

在任何以上工作完成前，不应把 R2–R9 当作已修复，也不应把理论风险当作已证实算法分叉。若未来目标从“ELF 行为等价研究”切换为“健壮通用模拟库”，则应另建分支：定义输入域、错误码、线程模型、数值容差、可移植 ABI、版本化 IPC 与独立物理验证；该分支的结果将不再保证 bitwise 模仿原 ELF。

## 6. 最终判断

目前 C 的**受控行为等价质量很强**，且本轮静态分析与受控 UBSan 没有发现新的正常路径问题；但是它不具备通用数值库、跨平台组件、线程安全库或安全工程软件应有的保护条件。最准确的工程表达是：它是一个在当前固定环境和已取证输入域内，通过原 ELF 双采集差分验证的离线行为等价重建；它不是原始源码，不是“全输入正确性证明”，更不能用于真实飞行、姿态控制、实体执行机构、任务决策或任何安全关键用途。
