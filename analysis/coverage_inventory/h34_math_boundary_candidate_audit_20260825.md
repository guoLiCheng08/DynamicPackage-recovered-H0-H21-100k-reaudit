# H34 数学边界候选审计

**日期：** 2026-08-25

H34 只在当前 Linux x86-64、离线调试副本和受控输入下工作。候选必须先由原 ELF 单步预筛证明稳定，且 state、global `y`、main 和 IPC 不出现 `NaN`/`Inf`，才允许进入双采集长时域；不以异常输入、无限值或资源破坏性测试构建结论。

## 发现

| 路径 | 与 H34 的关系 | 结论 |
|---|---|---|
| `DynamicInit` | 以 `Elements2PosVel_M` 将 `dyn_init` 的六个 `orbit_elements` 转为初始 GCI 位置/速度并写入全局 `y[7..12]` | 轨道根数不是死字段，会进入随后 `dyn_main` 的真实主传播路径。 |
| `CoreDynamic` | 每步先推进时间，再消费当前传播状态 | 根数与时间候选均能影响后续动力学和环境/遥测。 |
| `PosVel2Elements_M` | 已恢复出圆轨道 `e <= 1e-14` 与赤道 `abs(sin(i)) <= 1e-14` 的退化分支 | 应优先以有限、物理量级合理的圆赤道或近圆近赤道根数，覆盖明确阈值分支，而不是直接跳至接近抛物的 `e≈1`。 |
| `Elements2PosVel_M` | 使用 `M2E`、`sqrt(1-e^2)` 和三次旋转建立 GCI 初态 | `e=0`、`i=0` 仍是有界且可计算的候选；`e` 逼近 1 需先单步预筛。 |

## 首选预筛合同

首个 H34 候选取严格圆赤道根数：`a=7,000,000 m`、`e=0`、`i=0`、`RAAN=0.73`、`ω=1.17`、`M=2.41`。虽然圆/赤道情况下 RAAN 与近地点幅角并不唯一，但原接口仍接收这两个有限角值；该选择可使初始化与遥测反算经过已恢复的退化条件，同时保持半长轴、角度、时间、惯量、质量和其他初始量为正常有限值。

预筛将以 H32 已验证框架导出并扫描：初始化后的 `y`、一步后的 caller state、global `y`、main telemetry 与 IPC payload。仅当每个观察块均无 `NaN`/`Inf`，才建立 100/1000 步 first/second gold 与恢复端逐步比较。

> 本审计是测试选择说明，不是对圆轨道、赤道轨道、所有退化根数或任意输入的全域证明。工程仅用于离线研究、教学、受控仿真与回归，不得用于真实飞行、控制、实体执行机构或安全关键用途。

## 已完成的原 ELF 预筛与差分结论

圆赤道候选已按启动链执行：`DynamicDllInit` 后覆写初始根数，再由 `dyn_init` 生成全局传播状态，调用端 `core` 缓冲保持零初始化，设备命令全零并以 `srand(1)` 固定传感器随机起点。原 ELF 单步预筛导出了初始 `y`、一步 caller state、一步 global `y`、main 和 IPC；五个块的 double/float 文本扫描均未报告 `NaN` 或 `Inf`。初始 `y[7..12]` 的有限位置/速度值证明根数转换已进入传播状态，而不是仅写入未消费配置。

随后 100/1000 步各完成 first/second 独立采集；每种长度 state（264 B/步）、global `y`（264 B/步）、main（544 B/步）和 IPC payload（3000 B/步）共四个流均逐文件 `cmp` PASS。恢复端使用相同的 `DynamicDllInit → 修改根数 → dyn_init → dyn_main` 合同，100 步 400 条、1000 步 4000 条逐步块比较均为 0-byte mismatch；未发现需要修改恢复 C 源码的已证实分叉。
