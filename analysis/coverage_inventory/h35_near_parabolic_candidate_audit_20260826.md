# H35 近抛物高偏心候选审计

**日期：** 2026-08-26

H32 已覆盖 `a=42,000,000 m`、`e=0.75`，其近地点半径为 `10,500,000 m`。H35 选择仍为椭圆、但更接近抛物极限的 `a=700,000,000 m`、`e=0.99`。该候选的近地点半径为 `7,000,000 m`，远地点为 `1,393,000,000 m`，而根数转换中的 `sqrt(1-e²)=0.14106735979665884425`；它明显压缩高偏心计算余量，同时保持正半长轴、`0≤e<1`、有限三角函数输入和有限近地点半径。

| 项目 | H32 | H35 | 用途 |
|---|---:|---:|---|
| 半长轴 `a` | `42,000,000 m` | `700,000,000 m` | 扩展根数尺度 |
| 偏心率 `e` | `0.75` | `0.99` | 靠近椭圆/抛物边界而不越界 |
| 近地点 `a(1-e)` | `10,500,000 m` | `7,000,000 m` | 保持有限且高于地球参考半径 |
| 远地点 `a(1+e)` | `73,500,000 m` | `1,393,000,000 m` | 扩展远距离轨道状态 |
| `sqrt(1-e²)` | 约 `0.6614` | `0.14106735979665884425` | 直接压缩 `Elements2PosVel_M` 的根式项 |

轨道角固定为倾角 `0.85 rad`、RAAN `2.30 rad`、近地点幅角 `1.10 rad`、平近点角 `0.37 rad`，以避免同时混入圆/赤道退化；时间、惯量、质量、默认设备、零命令和随机种子遵循 H34 启动链基线。

## 原 ELF 单步预筛的校正方法与结果

最初对 main telemetry 全字节块同时按 `float` 和 `double` 文本解释。该做法在 offset `0x1e0` 报告 `NaN`，但该偏移已经由 `DP_TM_ORBIT_ELEMENTS` 证实为**对齐的 double 轨道根数数组**。把一个 double 的低/高四字节片段误作独立 float 解析，会产生伪 `NaN`；它不是原 ELF 输出的非有限 double。因此，H35 改为按已恢复布局进行字段对齐检查：初始化 `y`、caller state 与 global `y` 仅按 8 字节 double 扫描；main telemetry 的姿态、陀螺、DSS、磁强计、飞轮、SADA、GPS、传播前缀、ECEF 位置/速度和 orbit-elements 只在其已知 double 字段范围扫描。

校正检查结果为：`e=0.99` 单步的初始化 `y`、一步 caller state、global `y` 与 main 的已知 double 字段均未见 `NaN` 或 `Inf`。main `0x1e0` 的前四个 double 是有限值：`a=699999999.9992301`、`e=0.9900000000017579`、`i=0.849999999922629`、`RAAN=2.2999999998647374`。因此该候选符合 H35 长时域准入条件。此前为排查伪告警运行的 `e=0.95` 与 `e=0.90` 试探不构成 H35 结果，亦不纳入后续 gold 或覆盖统计。

> 本候选选择与预筛不表示对近抛物轨道、任何高偏心根数、物理可行轨道、任意长度传播或现实任务的认可。该工程仅用于离线研究、教学、受控仿真和回归，不得用于真实飞行、姿态控制、实体执行机构或安全关键用途。

## 已完成的 H35 双采集与恢复端差分

H35 已以 `DynamicDllInit → 覆写根数 → dyn_init → srand(1) → dyn_main` 执行 100/1000 步 first/second 独立原 ELF 采集。每种长度的 caller state（264 B/步）、global `y`（264 B/步）、main telemetry（544 B/步）和 IPC payload（3000 B/步）四个 gold 流逐文件 `cmp` 均一致。恢复端使用相同根数与启动链，在 100 步 400 条和 1000 步 4000 条逐步四块比较中均为 0-byte mismatch；没有发现需要修改恢复 C 源码的已证实分叉。
