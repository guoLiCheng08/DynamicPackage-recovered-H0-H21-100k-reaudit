# DynamicPackage 深度还原：等价目标与信息边界

## 结论

对于已经编译为 ELF 的 C 程序，不能仅依靠反编译保证找回**原始源码文本的 100%**。编译阶段会移除注释、宏、局部变量与类型名称，并将许多不同的源代码表达压缩为相同或近似的机器指令；优化还可能内联、消除、合并或重排函数。因此，“字面源码 100%”在没有源代码、调试信息、构建脚本或符号映射文件的条件下不是可证伪、也不是可验收的目标。

可建立并严格验证的目标是**接口、状态、数值和运行时行为等价**。该目标要求重建程序在受控输入、相同初始条件、相同浮点环境和相同时间步长下，产生与原 ELF 相同的共享内存读写、返回／退出行为、状态序列、遥测序列及错误边界行为。

## 目标分级

| 级别 | 定义 | 可验收方式 | 当前状态 |
|---|---|---|---|
| L0：可读骨架 | 从符号、字符串和反汇编恢复函数名与主要模块 | 人工审阅与静态证据 | 已达到 |
| L1：接口等价 | 共享内存、函数参数、结构体偏移、输入输出索引一致 | 读写探针、偏移断言 | 部分达到 |
| L2：控制流等价 | 初始化、调度、错误分支、循环和调用顺序一致 | 调用追踪与单元回归 | 部分达到 |
| L3：数值等价 | 核心状态导数、积分、设备／传感器输出逐步误差受控 | 同输入差分回归 | 尚未达到 |
| L4：行为等价 | 全部公开及异常路径、IPC、资源行为与原程序匹配 | 多场景黑盒回归 | 尚未达到 |
| L5：文本级源码相同 | 原变量名、注释、宏、排版与原仓库一致 | 只有获得原始仓库／调试工件可验证 | 仅凭 ELF 不可保证 |

## 对本样本的实际建议

本项目应以 L4 为高价值目标，并将 L3 的数值回归作为每个模块完成的门槛。即使 C 代码中的变量名和原开发者使用的标识不同，只要可在相同输入下产生同等的状态和遥测，并遵守相同 IPC 协议，即可成为可替换、可维护的功能等价实现。

要达到 L5，至少需要获得下列任意辅助工件之一：原始 Git 仓库、`.c/.h` 文件、构建脚本、未剥离的 DWARF 调试信息、`.o` 对象文件、链接映射文件、CI 构建产物或发行版源代码包。当前 ELF 保留函数符号但没有这些完整源码层信息，因此可支持深度功能恢复，但不能证明还原的标识符和源码文本完全等同于原文。
