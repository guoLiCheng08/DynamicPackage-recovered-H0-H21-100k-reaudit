# DynamicPackage 差分回归与数值等价验收规范

## 1. 双实现测试架构

测试框架应同时运行“原 ELF 参考实现”和“重建 C 实现”，但二者必须位于独立的私有共享内存命名空间中，避免复用 `/sharedvars_example`。控制器对两个实例写入完全相同的输入帧，按固定时间步采集各自完整的 IPC 输出帧和可选内部状态帧。所有输入帧、采样时刻、原始输出、恢复输出、差异和元数据都写入可重放数据集。

原 ELF 必须持续使用无网络、私有 `tmpfs`、CPU／内存／文件／进程限额和超时终止策略。重建程序亦在相同限制下运行，以避免测试框架本身引入行为差异。

## 2. 输入向量矩阵

| 类别 | 典型向量 | 覆盖目的 |
|---|---|---|
| 基线 | 全部控制命令为零 | 建立初始姿轨与传感器的参考轨迹 |
| 飞轮 | 单轮正／负阶跃、四轮组合、使能切换 | 验证轮速、角动量与姿态耦合 |
| MTQ | 三轴单独与组合力矩 | 验证磁力矩器和地磁耦合 |
| SADA | 位置模式、速度模式、限位值、模式切换 | 验证太阳翼驱动状态机与反馈 |
| 推进器 | 使能／禁用、脉冲、连续输入 | 验证外力、速度和轨道响应 |
| 初始轨道 | 近圆、椭圆、不同倾角、高度边界 | 验证根数转换和摄动实现 |
| 初始姿态 | 单位四元数、90° 旋转、接近奇异姿态 | 验证四元数归一化与姿态转换 |
| 边界与异常 | NaN 禁止、零向量、最大／最小合法参数、非法标志 | 验证错误路径、限幅和稳定性 |

每一类至少应包含固定基准向量和伪随机向量。伪随机向量必须使用记录在数据集中的种子，禁止依赖实时系统随机源。

## 3. 采集层次

| 层次 | 内容 | 采集方法 | 作用 |
|---|---|---|---|
| IPC 输入 | 全部 float／byte 命令区 | 控制器写入前镜像 | 确保两边输入相同 |
| IPC 输出 | 所有遥测 float／byte 区 | 写锁后完整快照 | 最终兼容性依据 |
| 33 维状态 | 四元数、角速度、位置、速度、扩展状态 | 调试构建导出或状态钩子 | 定位积分与物理模型误差 |
| 中间物理量 | 力矩、轮动量、惯量、坐标转换结果 | 分模块测试桥接器 | 在误差放大前定位根因 |
| 运行时事件 | 有效标志、错误码、打印、周期计数 | 日志与 IPC 标志 | 验证异常与状态机行为 |

## 4. 指标与容差

首先必须区分“按位一致”和“数值一致”。整数、标志、IPC 偏移、字段数量、帧顺序和错误码应按位一致。确定性的纯代数函数（如向量运算、四元数转换、编解码）目标为按位一致或 1 ULP 以内。涉及 `libm`、积分累计、时间或随机噪声的模型，采用分层容差。

| 对象 | 初始验收阈值 | 终验收阈值 | 说明 |
|---|---:|---:|---|
| IPC 字节／整数 | 完全一致 | 完全一致 | 不允许容差 |
| 纯线性代数 `double` | 1 ULP | 1 ULP | 统一编译器与舍入模式后比较 |
| 坐标／轨道转换 | `1e-12` 相对误差 | `1e-13` 相对误差 | 每个元素均应满足 |
| 单步姿态／轨道导数 | `1e-10` 相对误差 | `1e-12` 相对误差 | 先比较无噪声状态 |
| 100 步状态轨迹 | `1e-7` 相对误差 | `1e-9` 相对误差 | 容差随时间步累计但应可解释 |
| 传感器噪声输出 | 统计特征一致 | 随机序列一致或统计一致 | 取决于是否恢复随机状态 |

对于接近零的量，应使用绝对误差门槛替代相对误差。每次失败都要记录第一个超阈值时间步、字段、输入帧、原值、恢复值、绝对误差、相对误差和该字段的上游中间量。

## 5. 回归流程

第一步是为原 ELF 生成金标数据集：在隔离环境中运行每个测试向量，记录输入帧和连续状态／遥测快照。第二步是冻结该数据集并建立文件哈希。第三步是每恢复一个函数就对相关最小数据集运行单元回归；只有该模块通过，才允许合入上层集成。第四步是每日执行全量回归，生成误差趋势图和失败列表。

数值误差若集中出现在第 1 个时间步，优先检查 ABI、结构偏移、单位与符号。若在多步后缓慢增长，优先检查积分器、舍入顺序、时间步与物理常数。若在状态切换点突然出现，优先检查控制标志、限幅、初始化和随机状态。

## 6. 最终验收条件

达到功能等价（L4）的最低条件包括：所有已识别 IPC 输入／输出字段按位兼容；基线、命令阶跃和边界向量均完成；连续 100 步关键状态和遥测满足最终阈值；异常路径返回和有效标志一致；重建运行时可在私有 IPC 环境中替换原 ELF；全部测试数据、脚本、编译参数和哈希可复现。

文本级“100% 原始 C 源码”不作为验收指标，除非用户能够补充原始仓库或带类型／源路径的调试工件。对于该类工件，应先进行哈希校验、来源确认和与 ELF 的构建一致性比对，再将其作为恢复证据，而不是不经核验地覆盖当前工程。
