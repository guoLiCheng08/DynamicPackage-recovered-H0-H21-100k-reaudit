## 3. 执行规则

每个新增单元必须先从原 ELF 采集可复现金标，重复一次并执行逐字节 `cmp` 确认确定性；随后以最小 C11 比较器复放相同初态和命令；任何差异先定位到最早状态或对象边界，修复后再加入 `make selftest`。不以有限金标推断未采样输入的等价性。

## 4. 当前执行中的 P1 组合边界单元

下一条组合序列将以第 0 轮 `omega_limit + 0.1` 的正向超限状态开始，并同时保留其余三轮的零初态。命令周期拟依次覆盖：正向第 0 轮扭矩（验证阻断）、第 1/2 轮异号扭矩、MTQ X/Y 异号命令、推进器启用与关闭、以及第 0 轮反向命令（验证脱离饱和）。场景在非共线姿态与固定 `srand(1)` 下运行至少十步；原 ELF 金标须包括每步状态、主帧、IPC payload，且在超限阻断和反向脱离边界导出完整 4×0x78 飞轮对象、MTQ、推进器和群组角动量 backing。

该单元的目标不是推断未采样的执行器极限，而是将单轮两步边界证据扩展到多执行机构组合调度与持续状态路径。

## 5. 飞轮精确速度边界隔离单元

飞轮逻辑除“`omega > omega_limit` 且正向加速度”阻断分支外，还存在精确相等分支：当 `omega == omega_limit` 时，控制更新不会写入新的 `acceleration`，因此必须以**预置非零加速度**分别配合正、负命令取证，避免将其误判为普通零加速度限幅。该单元将分别采集：精确正上限、正上限以上、显著负向高转速，以及超出 `torque_limit` 的正负命令。对每个子场景，原 ELF 金标应至少包含完整 0x78 飞轮对象、群组角动量／力矩和隔离 `UpdateDeviceControl` 输出；端到端扩展时还比较 33 维状态、主帧与 IPC payload。
