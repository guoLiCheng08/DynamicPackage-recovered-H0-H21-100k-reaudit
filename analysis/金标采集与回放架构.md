# 原 ELF 金标采集与回放架构

## 架构目标

金标体系必须把原 ELF 从“黑盒偶发运行程序”变成“可重复查询的参考实现”。每一个后续恢复模块都从同一份输入数据集获得原始参考输出，并在独立环境中将重建输出与之逐项比较。

## 隔离实例拓扑

```text
测试向量库 ──► 原 ELF 受控实例 ──► 原始金标帧库
     │              │
     │              └─ 私有 user/mount/network namespace
     │                 私有 /dev/shm/sharedvars_example
     │                 只读原 ELF、资源限额、固定逻辑时钟
     │
     └──────────► 重建 C 受控实例 ──► 恢复输出帧库
                                      │
                                差分器／首差定位器
```

原 ELF 和重建程序永不共享同一个共享内存对象；二者只接收同一份序列化输入帧。这样可以排除并发、锁竞争和共享状态污染造成的伪差异。

## 金标数据包格式

每次执行生成一个不可变目录，包含输入、每步输出、环境元数据和完整性校验。

| 文件 | 内容 |
|---|---|
| `manifest.json` | 样本 SHA-256、工具链、动态加载器、库版本、CPU 特征、逻辑时钟策略、随机策略 |
| `case.json` | 初始参数、命令序列、采样步数、预期运行周期 |
| `input_frames.bin` | 每一逻辑步完整的共享内存输入区原始字节 |
| `output_frames.bin` | 每一逻辑步完整的共享内存输出区原始字节 |
| `frames.jsonl` | 每步偏移、已命名字段、时间戳、状态标志和人可读摘要 |
| `stdout.log` / `stderr.log` | 原程序日志，作为异常路径证据 |
| `environment.txt` | 命名空间、限制、内核和库版本记录 |
| `sha256sum.txt` | 以上所有文件及原样本的校验和 |

为避免未知字段遗漏，输出帧必须保存整个 `0xBF0` 字节共享内存区域，而不只是已经命名的遥测字段。差分器首先逐字节比较，再将首个偏移映射回已知字段或 `reserved_*` 区段。

## 输入测试集

第一批应建立以下固定数据集：零命令基线、单飞轮正／负阶跃、单轴 MTQ、SADA 模式与参数切换、推进器使能脉冲、初始参数边界、长时间零命令轨迹。每个用例至少采集 1、10、100、1,000 个逻辑步，分别用于 ABI 检查、短期数值定位、积分累积和稳定性观察。

第二批加入伪随机但固定种子的组合命令。每个生成器版本、种子和输入序列均必须存入 `case.json`；不得只记录“随机测试通过”。

## 时钟和随机性控制

要取得严格字节相同的金标，默认使用可控动态链接拦截层，包裹 `clock_gettime`、`clock_nanosleep`、`rand`、`srand` 及必要的 `libm` 调用。第一轮先记录原 ELF 的调用次序和返回值，第二轮向原 ELF 和重建程序重放相同序列。若某个调用不能安全拦截，则记录其影响范围并把相关字段从“位级等价”暂时降级为“统计等价”，但不得将其计入完全一致覆盖率。

## 首差定位器

差分器的输入是同一 case、同一逻辑步的两个完整帧。它按以下顺序输出诊断：第一处不同字节偏移；该偏移所在的命名字段／结构体；原始与恢复十六进制；若是浮点则输出 IEEE-754 位模式、绝对误差、相对误差和 ULP 距离；该字段的上游状态与最后一个已对齐逻辑步。报告禁止只输出平均误差，因为平均误差会掩盖严重的首步偏差。

## 阶段性成果

在任何高保真物理模型实现开始前，必须先完成金标采集器、完整帧存储、回放控制器和首差定位器。它们将使“理论推断是否正确”不再是主观判断，而能被每一次原 ELF 运行的具体字节结果验证。
